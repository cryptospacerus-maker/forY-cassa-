# Судья — отчёт о реализации и инструкция

Исторический отчёт о первой реализации. Текущий запуск описан в [инструкции Codex](../evaluation/README.md).


Дата: 24 ноября 2026. Карточка: https://github.com/cryptospacerus-maker/forY-cassa-/issues/10
Ветка: `feat/judge-agent`. Статус: реализован проверяемый MVP; живое подключение и запуск в Actions ещё требуют настройки и проверки.

## Что теперь есть

Создан независимый агент **Судья**, техническая роль `evaluator`.
По отдельной команде он получает точный коммит, требования и доказательства,
формирует предварительную конкурсную оценку и рекомендации. Не пишет код,
не назначает работу и не запускает других агентов.

| Компонент | Реализация |
|---|---|
| Рабочий профиль | `agents/evaluator.md`: независимость, полномочия, формат оценки |
| Профессиональная основа | `evaluation/jury-research.md`, подробное исследование в плане |
| Рубрика | `evaluation/rubric.json`: 22 критерия, сумма максимумов 100 |
| Контракты | JSON-схемы запроса и модельного ответа |
| Сбор материалов | Чтение файлов через Git по SHA; SHA-256 вычисляется из байтов |
| Модель | OpenAI Responses API, structured outputs, один запрос без автоматических повторов |
| Проверка ответа | Полнота критериев, диапазоны, допустимые ссылки, суммы обычным кодом |
| Отчёты | Markdown, JSON, манифест источников |
| Ручной workflow | `evaluate.yml`: подготовка → оценка → публикация |
| Доступы | Разрешённые логины + проверка прав GitHub; запуск workflow только main |
| Повторы | Резервирование request_id в карточке до платного вызова |
| Публикация | Обновление комментария, упоминание автора, ссылка на артефакты |
| Локальный вход | `python -m scripts.evaluator.launch` |
| Общие инструкции | Маршрут «Судья» добавлен в AGENTS.md; решение — в PROJECT.md |

Контрольный локальный коммит кода: `9ce402dd02552566421fea0fd0ef154841bfcb6c`.
Публикация через GitHub connector может создать другой commit SHA при том же дереве;
точный SHA опубликованной версии будет записан в карточке #10 и PR.

## Как вы будете общаться с Судьёй

После настройки в подключённом рабочем чате:

> Судья, оцени задачу №8, коммит [полный SHA], трек integrator,
> требования v1. Материалы — evaluation/evidence/manifest.json.

Агент инициатора читает профиль, фиксирует параметры и вызывает отдельный workflow.
Если у чата нет инструмента запуска, используйте кнопку **Actions → Судья → Run workflow**.
Фраза в произвольном чате сама по себе техническим триггером не является.

Судья отвечает:

1. Предварительной оценкой по критериям с доказательствами.
2. Сильными сторонами и причинами потери баллов.
3. Тремя главными улучшениями: действие, предлагаемый владелец, трудоёмкость, проверка.
4. Вопросами для репетиции защиты.
5. Перечнем того, чего он не смог проверить.

Отчёт приходит в карточку GitHub. Решаете, какие рекомендации принять, вы.
Игорёк распределяет принятую работу, Ксю/Тёма реализуют, Андрюха проверяет.
После исправлений — новая команда Судье на новый SHA. Отдельный аккаунт для роли не нужен.

## Что потребуется для первого реального запуска

1. Проверить и слить PR в main. До этого кнопка ручного workflow не активирована для этой поставки.
2. Добавить разрешённые GitHub-логины Семёна и Толи в `JUDGE_ALLOWED_ACTORS`.
3. Подготовить манифест файлов в оцениваемом коммите. В поставке есть учебный
   манифест с PROJECT.md и README.md, которого недостаточно для полной оценки.
4. Выполнить `dry-run`: он проверяет инфраструктуру без вызова модели и без баллов.
5. Настроить `JUDGE_OPENAI_API_KEY`, модель, бюджет и проверенные цены.
6. Новым request_id запустить `live`, проверить доставку и содержательность оценки.

Все команды, поля, переменные, лимиты файлов и примеры находятся в
[полной инструкции](../evaluation/README.md). Ключи не отправлять в чат и не коммитить.

## Что не проверено и что не реализовано

- Живой платный запрос к модели не выполнялся. В рабочем окружении нет предоставленного
  ключа для этой интеграции. Наличие repository secrets не удалось проверить через
  локальный gh: он не авторизован; значения секретов не запрашивались и не читались.
- Сквозной запуск GitHub Actions и доставка от имени обоих участников не выполнены.
  Нужны main с workflow, разрешённые логины и запуск после настройки.
- Содержательная калибровка на конкурсных работах с заранее согласованными ожиданиями
  ещё впереди. Есть проверка формата и контрольный ответ, но нет утверждения о точности баллов.
- Отдельной карточки/портрета Судьи в графической панели нет: панель и исходные слайды
  из #7 не менялись. Для запуска достаточно чата/Actions/CLI.
- Автоматическое пробуждение исходного личного чата не подключено.
- Самостоятельного браузерного тестирования, просмотра видео/PDF и скачивания URL нет.
  Их результаты поставляет команда/Андрюха; бинарные материалы отмечаются непроверенными.
- Нет суточного счётчика расходов, автоматического повторного судейства или кеширования
  одинаковых материалов под разными request_id. Повтор одного request_id защищён.
- Официальные источники зафиксированы на 24.11.2026; обновление рубрики делает команда
  перед оценкой. Модель не ищет новые правила самостоятельно.

Эти границы отражены в инструкции, чтобы команда не принимала технический прогон
за полноценное независимое заключение. Действующие роли, QA-автоматизация и пилот
не изменены. Сайт, его данные и ZIP не менялись; браузерная проверка сайта к этой
поставке не относится.

## Почему реализация немного проще полного плана

Для ограниченного бюджета оставлен один модельный запрос без автоматического
исправления ответа повторным платным вызовом. Невалидный ответ даёт blocked.
Постоянный сервер и БД не нужны. Публикация вынесена в отдельный job с правами записи,
а в job модели этих прав нет; код целевой ветки не исполняется.

Следующий шаг команды — review PR, настройка и dry-run, затем один контролируемый
live-прогон. После него можно решать, нужны ли интерфейс, доставка в чат и расширенная
калибровка. Код MVP и инструкция готовы к такому прогону.
