# Судья в Codex

Семён или Толя запускает оценку в отдельной сессии Codex с доступом к GitHub.

> Судья, оцени задачу №8, коммит <полный SHA>, трек integrator, версия требований pilot-contract-v1. Манифест evaluation/evidence/manifest.json. Опубликуй отчёт в задаче №8.

Оценку выполняет открытая сессия Codex в пределах лимитов аккаунта. Python локально собирает материалы из Git, проверяет отчёт и формирует Markdown и JSON. Для публикации сессия использует подключение к GitHub. Настройка платного OpenAI API и GitHub Actions для «Судьи» больше не требуется. Отдельная сессия запускается человеком по команде в Codex.

## Порядок работы сессии

1. Прочитай профиль [Судьи](../agents/evaluator.md), актуальные AGENTS.md и PROJECT.md из main, карточку и комментарии через GitHub. Укажи блокировку, если контекст или точный SHA недоступны. Проверь существующие отчёты в карточке. При повторе используй новый request_id и явно зафиксируй основание.
2. Используй чистый доверенный checkout инструкций и инструментов из main. Получи Git-объект целевого коммита. Читай исходники и манифест по SHA, без исполнения кода из оцениваемого коммита.
3. В черновой папке создай request.json по [схеме](schemas/input.json) и context.json с объектами github_issue и main_instructions. Первый содержит заголовок, описание и комментарии карточки со ссылками. Второй содержит актуальные AGENTS.md и PROJECT.md. Укажи дату получения контекста. Храни черновики вне коммита.
4. Установи зависимости доверенного инструмента и собери пакет. Команда вернёт SHA-256 файла packet.json.

```bash
python3 -m pip install -r evaluation/requirements.txt
python3 -m scripts.evaluator.run prepare \
  --request .judge-output/request.json \
  --context .judge-output/context.json \
  --output .judge-output/judge-001
```

5. Прочитай packet.json, [рубрику](rubric.json) и [схему оценки](schemas/report.json). Оцени каждый критерий в этой сессии. Запиши assessment.json с ключом packet_sha256 (хеш из шага 4) и ключом assessment (объект по схеме). Значение null означает недостаток доказательств. Ноль требует доступного доказательства отсутствия результата.
6. Проверь и сформируй отчёт.

```bash
python3 -m scripts.evaluator.run finalize \
  --assessment .judge-output/assessment.json \
  --output .judge-output/judge-001
```

7. Прочитай report.md. Опубликуй проверенный результат в исходной карточке, если пользователь поручил публикацию. Укажи SHA, версию кейса и request_id. При недоступности записи верни отчёт в чат и укажи блокировку. Пакет с исходным контекстом оставь локальным.

Выходные файлы — report.md, report.json, manifest.json. Статус reviewed означает, что оценены все критерии, partial — что по части критериев не хватило доказательств. При ошибке сборки или проверки команда завершится с ненулевым кодом. Недействительный отчёт к публикации не готов.

## Материалы

Манифест хранится в целевом коммите. Пример элемента:

```json
{"items":[{"id":"requirements","path":"PROJECT.md","kind":"requirements","source_sha":"target"}]}
```

Указывай полный SHA сборки, проверенной в QA-отчёте. Значение target подходит для исходников и требований из оцениваемой версии. Просроченные QA-доказательства исключаются из баллов. Пакет ограничен 30 файлами, 100 КБ на файл и 240 КБ суммарно с контекстом. Для бинарных файлов фиксируется SHA-256. Добавь расшифровку для слайдов и видео и явно укажи, что реально просмотрено. Исключи секреты и клиентские персональные данные.

Проверка инструмента — `python3 -m unittest discover -s tests -v`.
