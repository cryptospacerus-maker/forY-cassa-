# Правила совместной работы

1. При старте прочитай `PROJECT.md`, свою карточку вместе с комментариями и список активных задач. Уточни, какая сессия назначена исполнителем и какой результат ожидается.
2. Семён или Толя закрепляет каждую задачу за одной сессией. Отметь начало работы в карточке. Если область изменений пересекается с чужой задачей, согласуй границу до редактирования.
3. Перед использованием чужого результата и перед сдачей перечитай связанные решения и карточки. Если меняется общее требование, перечисли затронутые задачи. Семён или Толя фиксирует согласованное решение в `PROJECT.md` и сообщает активным сессиям, что перечитать.
4. При передаче опубликуй рабочую версию и запиши в карточке четыре пункта: что готово, ссылка на версию, что проверено, ближайший шаг. Укажи нового исполнителя.
5. При завершении приложи ссылку на результат и опиши фактическую проверку по критерию готовности. Если проверка ещё впереди, укажи, что осталось проверить.

## Перед каждым запросом по проекту

Открой актуальные версии AGENTS.md и PROJECT.md из main. Посмотри открытые задачи, включая работу соседних сессий. Со времени последней сверки проверь обновлённые Issues (включая закрытые), PR и коммиты. Для новой сессии начни с обзора истории проекта. По теме запроса прочитай решения, комментарии и результаты проверок, включая связанные завершённые задачи. Если появились изменения, скорректируй план до начала работы. Если GitHub недоступен, явно укажи, на какую версию опираешься и что осталось сверить.

После содержательного изменения сохрани в карточке решение, причину, статус, ссылку на результат и следующий шаг. При наличии зависимостей укажи связанные карточки. Между запросами оставляй точку последней сверки в текущей задаче (время UTC и, для кода, коммит). Для вопроса без новых решений достаточно ответа в чате.

Во время параллельной работы повтори сверку перед использованием общего результата и перед публикацией. Если общее решение изменилось во время выполнения, сообщи затронутым сессиям и сверь их результаты с новой версией.

## Отдельная команда «Судья»

По явному запросу пользователя «Судья, оцени…» используй `agents/evaluator.md`.
Это независимая роль `evaluator`, не обязательный этап разработки. Сначала
уточни объект и зафиксируй полный SHA, трек, версию кейса и материалы для оценки.
Команда без определённой версии не запускает платный workflow. Для автоматического
запуска используй инструкцию `evaluation/README.md`; не обещай, что запуск выполнен,
пока не получен ID запуска. Без настроенного доступа сообщи точную блокировку.
Судья не меняет продукт, не назначает задачи и не заменяет QA Андрюхи.
