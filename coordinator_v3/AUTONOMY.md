# Следующая задача: автоматический импорт и доставка Coordinator V3

После приёмки ручного маршрута включить автоматизацию отдельным флагом. За основу взять существующие admission, SQLite и ручной протокол публикации. До согласования инфраструктуры запускать тесты с локальным Git и имитатором GitHub.

| Компонент | Объём | Критерий |
| --- | --- | --- |
| Watcher | Читать комментарии с пагинацией, перекрытием границы времени и постоянным курсором. Сохранять ID, время и версию события вместе с результатом разбора. Перепроверять комментарий перед допуском. | Повтор страницы, равные timestamps, редактирование, удаление и рестарт не теряют команду и не создают второй run. |
| Авторизация GitHub App | Разделить чтение и публикацию, проверять установку, репозиторий и разрешения, обновлять краткоживущие installation tokens. Держать ключи вне Git и процессов Worker. | Отзыв, истечение и неверный репозиторий блокируют выдачу и запись. Ключи отсутствуют в audit и аргументах процессов. |
| Publication outbox | Атомарно создавать запись доставки при завершении run. Отдельно хранить ожидаемый Git ref и состояние комментария. Проверять точный SHA, маркер и служебного автора. | Потеря подтверждений push и POST восстанавливается по истории. При неопределённом POST требуется сверка, повторной отправки вслепую нет. |
| Эксплуатация | Метрики пропускной способности и возраста очереди, наблюдение за Worker и QA, лимиты на инициатора, консервативное хранение и архивирование. | Нагрузка, rate limit, purge и восстановление не снимают ограничения C1. |

Граница этого этапа V3 — ручной `ingest`, автоматическая обработка принятой задачи и ручной `publish` с устойчивым маркером `posting`. Автономные watcher, курсор и фоновая публикация требуют отдельного ревью. Запуск модели остаётся под согласованным контролем владельцев.
