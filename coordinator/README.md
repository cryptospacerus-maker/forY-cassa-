# Coordinator MVP

Координатор принимает номер GitHub Issue. Игорёк составляет критерии и план, Тёма и Ксю выполняют нужные части, Андрюха проверяет SHA результата. При дефекте координатор передаёт его исполнителю на одну доработку. Затем он публикует итог в исходном Issue и упоминает аккаунт, запустивший работу.

## Локальный запуск

Из корня репозитория, с Python 3.11+ и Git:

```sh
python3 -m coordinator run --issue 13 --fixture --mode dry-run
python3 -m unittest discover -s coordinator/tests -v
```

С `gh auth login` можно прочитать реальную карточку под своим GitHub-аккаунтом:

```sh
COORDINATOR_ACTORS='greatsoutherntrendkill tolyapolya2006-png' \
  python3 -m coordinator run --issue 13 --actor greatsoutherntrendkill --mode dry-run
```

Для локального режима `demo` требуются Codex CLI 0.172.0, переменные окружения `CODEX_API_KEY` и `COORDINATOR_MODEL`. Запуск `python3 -m coordinator run --issue 13 --fixture --mode demo` создаёт локальный Git-коммит при успешном результате. SHA будет в отчёте. Посмотреть результат можно командой `git show <SHA>:coordinator/demo/output/topic-counts.json`. Локальный запуск сохраняет состояние в `.git/coordinator` или по пути `--state`. Для другого запуска задайте новый `--request`.

## Настройка GitHub Actions

После ревью и попадания workflow в `main` откройте **Settings → Secrets and variables → Actions** в репозитории.

| Вид | Имя | Значение |
| --- | --- | --- |
| Variable | `COORDINATOR_ACTORS` | `greatsoutherntrendkill tolyapolya2006-png`. Каждый участник в списке также должен иметь права записи в репозиторий. |
| Secret | `COORDINATOR_OPENAI_API_KEY` | Ключ отдельного API-проекта OpenAI с доступом к модели для Codex CLI. Для dry-run ключ не нужен. |
| Variable | `COORDINATOR_MODEL` | Идентификатор совместимой модели из API-проекта. |
| Variable | `COORDINATOR_USD_PER_MTOK` | Опционально. Три актуальных тарифа через запятую по порядку: вход, кэшированный вход, выход. Единица — USD за 1 млн токенов. |
| Variable | `COORDINATOR_PATHS` | Только для режима `task`. Каталоги через пробел, например `sandbox/docs sandbox/app`. |
| Variable | `COORDINATOR_DRAFT_PR` | Опционально. `true` создаёт черновик PR с результатом, если это разрешено для Actions в настройках репозитория. По умолчанию итог указывает на опубликованный коммит в отдельной ветке. |

У Codex CLI есть вход через ChatGPT, API-ключ и другие корпоративные варианты авторизации. Для этого CI используется API-ключ. Расход оплачивается по тарифам API-проекта, отдельно от включённого в подписку использования ChatGPT. Оценка в Issue рассчитывается по введённым тарифам. Лимиты координатора — восемь сессий на запрос, одна доработка, 120 секунд на вызов и порог 180 тыс. уже учтённых токенов перед стартом следующей группы. Последняя группа может превысить порог. Тайм-аут или ошибка API могут оставить расход без телеметрии. [Авторизация Codex](https://learn.chatgpt.com/docs/auth) · [Неинтерактивный режим](https://learn.chatgpt.com/docs/non-interactive-mode) · [Тарифы](https://learn.chatgpt.com/docs/pricing)

## Команда из Codex

Передайте в рабочий чат Codex: «Создай открытый Issue в `cryptospacerus-maker/forY-cassa-` с задачей и критериями. Из моего GitHub-аккаунта запусти `coordinator.yml` на `main` и верни ссылку на запуск». Для первого прогона можно переиспользовать [контрольную карточку #13](https://github.com/cryptospacerus-maker/forY-cassa-/issues/13). Сначала запустите dry-run, затем demo:

```sh
gh workflow run coordinator.yml -R cryptospacerus-maker/forY-cassa- \
  --ref main -f issue=13 -f request=pilot-1 -f mode=dry-run
gh workflow run coordinator.yml -R cryptospacerus-maker/forY-cassa- \
  --ref main -f issue=13 -f request=pilot-1 -f mode=demo
```

Каждый из двух участников запускает команду под собственным GitHub-логином. Совпадающие ключи разных участников учитываются отдельно. Режим demo предполагает условия #13 и сверяет JSON по известному контрольному примеру. В режиме task каталог должен быть разрешён настройкой, а в Issue должны быть описаны требования и проверяемые критерии. Для запуска после изменения требований назначьте новый ключ. Для восстановления прерванного запроса выберите **Re-run all jobs** у исходного запуска, пока его артефакт доступен.

## Подключение ролей

Профили Игорька, Тёмы, Ксю и Андрюхи взяты без изменений из [версии PR #7](https://github.com/cryptospacerus-maker/forY-cassa-/tree/2e57707d45da18929ab840040a2da2a0210b722a/agents). До появления профилей в `main` рабочие копии размещены в `coordinator/profiles/`. При обновлении профиля зафиксируйте исходный SHA и пересмотрите инструкции роли в `coordinator/runner.py` и схему плана. Для новой рабочей роли добавьте тип в схему, правила маршрутизации и проверку передачи данных в тестах.

CLI запускает отдельную сессию для каждой роли с ограниченным набором исходных файлов. Роли возвращают полное содержимое предложенных текстовых файлов. Координатор проверяет, какие пути разрешены, и сам создаёт коммит. Параллельные роли получают непересекающиеся пути и отдельные рабочие каталоги. QA видит содержимое Git-коммита и его SHA. В demo дополнительно запускается детерминированная проверка JSON. В task проверка ограничена содержимым, переданным модели. Для подтверждения сборки или браузерного сценария потребуется отдельная доверенная проверка.

«Судья» использует свой маршрут из #11. Действующий сценарий Андрюхи для сайта, панель #7 и пилот #9 ведутся в своих ветках. Подробности о границах MVP и испытаниях приведены в [отчёте](REPORT.md).
