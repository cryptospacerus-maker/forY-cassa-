# Coordinator MVP

Координатор запускает рабочие роли из GitHub Issue. Игорёк составляет план для обычной задачи. Тёма и Ксю готовят изменения в разрешённых файлах, Андрюха проверяет конкретный SHA. При дефекте возможна одна доработка. Итог и сообщение об аварии приходят в исходный Issue с упоминанием инициатора.

## Первый живой запуск

1. После ревью и согласованного слияния PR #14 проверьте, что оба workflow появились в `main`. В [Settings → Environments](https://github.com/cryptospacerus-maker/forY-cassa-/settings/environments) создайте `coordinator-live`, разрешите деплой только с ветки `main` через **Selected branches and tags** и добавьте секрет окружения `COORDINATOR_OPENAI_API_KEY`. Храните его на уровне этого окружения. Включите правила защиты `main` согласно процессу ревью команды. Для запуска без дополнительных действий на каждый запрос окружение может работать без обязательного ручного подтверждения.
2. В [Settings → Secrets and variables → Actions → Variables](https://github.com/cryptospacerus-maker/forY-cassa-/settings/variables/actions) задайте параметры из таблицы ниже. Для первого прогона достаточно списка инициаторов и модели. Используйте ключ отдельного API-проекта с доступом к выбранной модели. API тарифицируется отдельно от подписок ChatGPT. [Авторизация Codex](https://learn.chatgpt.com/docs/auth)
3. Семён и Толя из своих сессий Codex сначала запускают один и тот же запрос в режиме dry-run. Убедитесь, что `gh api user --jq .login` возвращает их собственные логины. Дождитесь двух отчётов с разными авторами запуска. В них должно быть ноль сессий и ноль токенов.
4. Повторите dry-run от одного участника с тем же ключом. Новый Actions run может появиться, а повторных сессий и итогового комментария для этого участника быть не должно.
5. Один участник запускает `demo` по [контрольной карточке #13](https://github.com/cryptospacerus-maker/forY-cassa-/issues/13). Используйте исходный заголовок и текст карточки. Успешный прогон без доработки делает два запроса на генерацию, по одному на Тёму и Андрюху. В отчёте проверьте автора, SHA, результаты QA и токены. Файл `coordinator/demo/output/topic-counts.json` в этом SHA должен содержать `доставка=2`, `оплата=1`, `возврат=1`.
6. После сверки первого результата повторите `demo` из второй сессии, если нужно подтвердить живую приёмку с обоих аккаунтов. Запишите в #12 оба Run ID, ссылку на проверенный коммит, факт доставки каждому участнику и расход. Для проверки аварийного канала отдельно можно отменить новый dry-run после комментария «Запрос принят» и проверить одно уведомление об отмене.

| Где | Имя | Значение |
| --- | --- | --- |
| Repository Variable | `COORDINATOR_ACTORS` | `greatsoutherntrendkill tolyapolya2006-png`. Оба логина должны иметь право записи. |
| Repository Variable | `COORDINATOR_MODEL` | Для контрольного прогона можно использовать `gpt-5.4-mini`, если она доступна вашему API-проекту. |
| Environment Secret | `COORDINATOR_OPENAI_API_KEY` | Ключ окружения `coordinator-live` с ограничением ветки `main`. Для dry-run ключ не используется. |
| Repository Variable | `COORDINATOR_USD_PER_MTOK` | Опционально. Тарифы за 1 млн токенов через запятую в порядке вход, кэшированный вход, выход. Для `gpt-5.4-mini` на момент проверки это `0.75,0.075,4.50`. |
| Repository Variable | `COORDINATOR_PATHS` | Только для режима `task`. Разрешённые каталоги через пробел, например `sandbox/docs sandbox/app`. |
| Repository Variable | `COORDINATOR_DRAFT_PR` | Опционально. `true` публикует черновик PR результата, если политика Actions разрешает создание PR. По умолчанию публикуется только ветка и ссылка на коммит. |

## Одна команда из Codex

> Запусти Coordinator MVP для Issue #13 в cryptospacerus-maker/forY-cassa- в режиме dry-run с ключом pilot-check-1. Воспользуйся моим текущим GitHub-аккаунтом, покажи его логин и ссылку на запуск. При повторе используй тот же ключ.

Сессия Codex должна иметь авторизованный пользователем `gh`. Команда, которую она выполняет после проверки логина:

```sh
gh workflow run coordinator.yml -R cryptospacerus-maker/forY-cassa- \
  --ref main -f issue=13 -f request=pilot-check-1 -f mode=dry-run
```

Для платного демо замените `mode=dry-run` на `mode=demo` и используйте согласованный ключ `pilot-live-1`. Ключ учитывается в разрезе репозитория, Issue, инициатора и режима. Подробности для сессии приведены в [профиле инициатора](../agents/initiator.md).

## Бюджет и сбои

Перед каждой генерацией координатор вызывает счётчик входных токенов Responses API. Резерв проверяется атомарно для всех рабочих ролей. На сессию выделяется один запрос генерации, без повторной отправки при сетевом сбое. API ограничивает выход с учётом токенов рассуждения. Один вызов Codex ограничен 120 секундами.

| Режим | Запросы генерации | Суммарный вход | Выход на запрос |
| --- | ---: | ---: | ---: |
| dry-run | 0 | 0 | 0 |
| demo | 4 | 32 000 | 768 |
| task | 8 | 100 000 | 2 400 |

Успешный demo без исправления обычно делает два из четырёх запросов. Для `gpt-5.4-mini` по приведённым тарифам верхняя оценка генерации одного demo — **$0.038** без учёта кэша, при полном резерве входа и выхода. Отчёт показывает отдельно резерв и фактическую телеметрию, если она получена. При неизвестном исходе подключения расход сверяют в API-проекте. Лимит применяется к одному ключу запуска. [Подсчёт токенов](https://developers.openai.com/api/reference/resources/responses/subresources/input_tokens/methods/count) · [Модель и тарифы](https://developers.openai.com/api/docs/models/gpt-5.4-mini)

Обработанная ошибка попадает в обычный итог Issue. Для отмены или падения после записи «Запрос принят» отдельный workflow проверяет событие GitHub и публикует одно аварийное уведомление, если итог ещё отсутствует. До принятия запроса статус доступен в Actions. Восстановление выполняется через **Re-run all jobs** у исходного запуска. Платный повтор использует только завершённый артефакт, чтобы восстановить публикацию. При пропаже или незавершённости артефакта модели повторно не вызываются. Перед новым ключом проверьте расход и причину сбоя. Артефакты хранятся семь дней.

## Локальная проверка и профили

```sh
python3 -m coordinator run --issue 13 --fixture --mode dry-run
python3 -m unittest discover -s coordinator/tests -v
```

Транспортный тест требует Codex CLI 0.172.0. При отсутствии этой версии тест пропускается локально, CI устанавливает её автоматически. Для реального локального dry-run используйте `gh` и `COORDINATOR_ACTORS='greatsoutherntrendkill tolyapolya2006-png'` с аргументом `--actor`, соответствующим вашему логину. Состояние сохраняется в `.git/coordinator` или по пути `--state`. Локальный live-demo требует `CODEX_API_KEY` и `COORDINATOR_MODEL` в окружении.

Единственные копии четырёх рабочих профилей лежат в [agents](../agents/). Исходный текст совпадает с профилями из PR #7. Автоматические правила добавляются из [протокола](../agents/protocol.md), где общая часть дополняется только разделом нужной роли. Новую роль добавляют в профили, протокол, схему плана и тесты передачи. Режим task поддерживает текстовые изменения в разрешённых каталогах. Предложения по выполнению кода, тестов, подключению MCP и браузеру приведены в [отчёте](REPORT.md).
