# Контракт журнала Coordinator

Версия схемы — **2**. Каждый файл `events.jsonl` содержит по одному JSON-событию на строку. Машиночитаемая схема описывает обязательные поля, точные Git SHA и доказательства проверок. [JSON Schema](events.schema.json)

- Ключ события — `repository`, `run_id`, `sequence` для GitHub-запусков. `sequence` начинается с единицы и задаёт порядок независимо от совпадения меток UTC. Локальный синтетический запуск использует собственный `run_id`.
- GitHub-события содержат `issue`, `initiator`, `mode` и `workflow_run_id`. Роли — `analyst`, `developer`, `interface`, `tester`. Роль оценщика не входит в схему координатора.
- `coordinator.started` сохраняет базовый SHA и разрешённый маршрут. `plan.accepted`, `agent.started`, `agent.finished` и `task.handoff` описывают план, сессии и передачи. `mcp.read` показывает ID инструмента и использование кэша. `requirements.changed` и `repair.requested` обозначают остановку по изменившимся требованиям и назначенную доработку.
- `qa.started` и `qa.finished` содержат один SHA на раунд. `check.finished` V2 добавляет `evidence` с именем проверки, статусом, кодом выхода, размером и хешем вывода. Утверждение о публикации делается по `publication.finished.published_sha`; итоговое `sha` раньше этого события означает проверенный кандидат.
- `coordinator.finished` завершает работу ролей. `publication.finished`, `publication.failed` и `publication.skipped` описывают Git и доставку. `notification=issue-comment` означает, что GitHub принял комментарий; фактическая доставка зависит от настроек пользователя. В V2 внутренний итог движка `run.finished` может предшествовать общему итогу.
- `summary.json` содержит компактный снимок для отображения. Потребители могут игнорировать новые поля и незнакомые типы событий текущей версии. Для несовместимых изменений требуется новый номер схемы.

В Actions промежуточный артефакт `coordinator-state-<попытка>` содержит состояние и журнал вычислений. Артефакт `coordinator-journal-<попытка>` дополнен издателем; для панели выбирайте артефакт издателя самой свежей доступной попытки и избегайте объединения одинаковых последовательностей. При падении до загрузки артефакта журнал может отсутствовать. Аварийный наблюдатель в этом случае доставляет статус в Issue и ссылку на Actions.

Журнал не хранит исходный текст Issue, промпты, содержимое файлов, токены доступа, сырые ответы MCP и stdout песочниц. Служебный артефакт состояния включает данные, необходимые для восстановления публикации. Публичный характер репозитория учитывается при выборе задач и файлов.
