# Coordinator MVP. Отчёт о готовности к первому запуску

## Что изменено в PR #14

- Четыре работающих профиля перенесены в `agents/`. Они совпадают с #7 побайтно. Координатор читает профиль напрямую и дополняет общей частью и соответствующей ролью из `agents/protocol.md`. Добавлен `agents/initiator.md` с одной командой для сессии Codex. Поддерживать вторую копию профилей больше не требуется.
- Диспетчер принимает задания на `main`. Закрепление в Issue связывает ключ, режим, номер карточки и проверенного инициатора. Координатор собирает изменения в Git-индексе и сохраняет точный SHA. Публикация сверяет принятый SHA, текущие требования и разрешённые пути.
- Для контрольного demo используется готовый план. Независимая проверка JSON выполняется по Git-коммиту, а Андрюха подтверждает тот же SHA. Одна доработка доступна при дефекте. Живой demo с первого раза должен использовать два запроса на генерацию.
- Добавлен бюджетный шлюз для Codex CLI. Вход считается до генерации. Шлюз резервирует лимит на все параллельные сессии, устанавливает `max_output_tokens` и принимает только один запрос на сессию. Привязанный к публикации повтор после сбоя не запускает новые платные сессии.
- Добавлен независимый workflow уведомления. Он получает завершённое событие доверенного запуска с `main`, сверяет сохранённое закрепление и сообщает инициатору об аварии или отмене, когда итог отсутствует.

## Ревью безопасности

| Поверхность | Что проверено и изменено |
| --- | --- |
| Запуск и полномочия | Проверяются автор события, список допущенных логинов и право записи в GitHub. Входы workflow передаются как переменные окружения и цитируются в командах. Номер Issue, режим, ключ и SHA валидируются. |
| Недоверенные карточки | Заголовок, текст, исходники и результаты ролей подаются как данные. В контекст входят комментарии инициатора. В demo используются зафиксированные синтетические данные. Сторонний комментарий не может симулировать запись бота. Инструкции из Issue не назначают инструменты, модель, пути, права или получателя. |
| Полномочия модели | Сессии стартуют в отдельных временных каталогах с отключёнными shell, MCP, плагинами, поиском и вложенными агентами. Шлюз сверяет модель, принимает текстовые сообщения, игнорирует запрос на инструменты и отправляет фиксированный набор параметров к OpenAI. Результат валидируется, файлы не исполняются, публикация разрешена только по назначенным путям. |
| Секреты | API-ключ используется шагом координатора в защищённом окружении `coordinator-live`. Он остаётся у шлюза. CLI получает временный локальный токен, а GitHub-токен в среду CLI не передаётся. Для чтения, публикации и аварийного комментария выданы отдельные права. Деплой ограничивает окружение веткой `main`; соответствующую настройку выполняет администратор. |
| Аварийная доставка | Workflow наблюдения использует код доверенного `main` и метаданные GitHub. Он не открывает артефакты и ветки из исходного запуска. Комментарий требует записи о принятии именно этого запроса. Повторное событие, успешный итог и более свежая попытка подавляют повторное уведомление. |
| Бюджет и повтор | Перед генерацией резервируется вход и задаётся предел выхода. Ошибка связи не допускает повторной генерации с тем же пропуском. Платная попытка с тем же ключом при отсутствии завершённого состояния останавливается. Перезапуск отдельных job не выдаёт повторное разрешение на исполнение. |
| Публикация | Текст агента в отчёте не формирует активные ссылки и упоминания. Результат записывается в отдельную ветку после сверки SHA и требований. Защита `main` и права на настройки репозитория остаются у владельца. |

Репозиторий публичный. Issue, исходные файлы, артефакты и результаты ролей подходят только для данных, которые разрешено раскрывать. Шлюз использует `store=false` в Responses API. Настройки хранения и доступа на стороне API-проекта учитываются отдельно. Точный расход при сетевом разрыве может отсутствовать в телеметрии. Для проверки доступа до принятия запроса и недоступности самого GitHub остаётся журнал Actions. [Подсчёт входа](https://developers.openai.com/api/reference/resources/responses/subresources/input_tokens/methods/count) · [Ограничение выхода](https://developers.openai.com/api/reference/resources/responses/methods/create) · [Событие workflow_run](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#workflow_run)

## Проверки

Локально прошли 30 автотестов и проверка обоих workflow с помощью `actionlint`.

| Критерий | Статус и свидетельство |
| --- | --- |
| Одна команда, запуск из двух сессий | Частично проверено. Реальный GitHub API подтвердил `write` у обоих логинов. CLI прочитал #13 под текущим логином. Оба dispatch из собственных сессий проверяются после развёртывания на `main`. |
| Запуск ролей и передача результата | Частично проверено. Тесты покрывают план, зависимости, пересылку результата и два вызова для demo. Реальный Codex CLI 0.172.0 прошёл через шлюз с подменённым OpenAI API. |
| QA точного SHA и цикл исправления | Частично проверено. Автотест создал два реальных Git-коммита, отклонил первый, повторил QA и принял исправленный. Ответы ролей подменялись. |
| Отчёт и доставка | Частично проверено. Проверены сборка отчёта и один комментарий с корректным упоминанием. Фактическая доставка уведомлений GitHub обоим участникам остаётся на приёмке. |
| Авария и восстановление | Частично проверено. Тесты покрывают тайм-аут CLI, событие отмены, отсутствие закрепления, новый run attempt, повтор события и запрет платного запуска после потери состояния. Реальное событие отмены на `main` ещё не прогонялось. |
| Лимиты запросов и токенов | Проверено на тестовом провайдере. Две конкурентные сессии не могут взять один бюджет, пересечение лимита блокируется до генерации, сетевой обрыв не разрешает повтор запроса. Фактическая оплата OpenAI проверяется на live-demo. |
| Исходные компоненты и профили | Сверено по diff и SHA источника. Панель, бизнес-пилот и независимый «Судья» остаются в своих ветках. Канонические профили совпадают с #7, правила автоматики живут в одном протоколе. |
| Возврат в исходный чат Codex | Не подтверждён. MVP доставляет итог через GitHub Issue. SDK описывает продолжение управляемой интеграцией сессии, а Work предоставляет свой канал событийных уведомлений. [Codex SDK](https://learn.chatgpt.com/docs/codex-sdk) · [Событийные задачи Work](https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt) |

Доступная GitHub-учётная запись имеет право записи, но не администрирования репозитория. Окружение `coordinator-live` при сверке отсутствовало. Развёртывание, настройку окружения и живой запуск с минимальным расходом описывает [пошаговый сценарий](README.md#первый-живой-запуск).

## Безопасное расширение для следующих итераций

1. **Выполнение кода и тесты.** Добавить отдельный проверяющий job для явно выбранного SHA. Запускать код в одноразовой песочнице без ключей, GitHub-токена, хостовых каталогов, Docker socket и сети. Тестовые команды определять в проверенной конфигурации `main`, передавать аргументы отдельно. Ограничивать CPU, память, диск, сетевой доступ и время. Сохранять SHA, коды возврата и усечённые журналы. Публикацию ведёт существующий доверенный job.
2. **MCP.** Подключать конкретные инструменты через отдельный шлюз с проверкой схемы и разрешённых операций, начиная с чтения тестовых данных. Токены тестового сервиса остаются у шлюза. Запросы на запись и доступ к чувствительным данным требуют отдельного явного согласования и учёта.
3. **Браузер.** Запускать тесты Playwright по синтетическим данным на локальном сервисе того же SHA, в чистом профиле без сохранённых сессий, с сетью, ограниченной стендом. Передавать только результат шага, скриншот и журнал проверки без секретов.
4. Включать каждую возможность отдельной настройкой после проверки границ и повторного ревью. Первый demo использует текстовый контракт и детерминированную проверку JSON.
