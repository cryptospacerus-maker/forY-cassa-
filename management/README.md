# Management Layer MVP

Проект для согласования в [Issue №22](https://github.com/cryptospacerus-maker/forY-cassa-/issues/22). База — `main` на `476444397c48183d04a3e856e742a33af93fa93f`, включая [PR №21](https://github.com/cryptospacerus-maker/forY-cassa-/pull/21).

Семён и Толя обсуждают решения каждый в своём чате ChatGPT и управляют работой каждый из своей сессии Codex. Они передают ссылку на GitHub Issue и короткую команду. Codex сам сверяет карточку, коммиты, проверки и решения по доступным источникам. GitHub хранит согласованную версию задачи и опубликованный результат. Доступ к истории чужого или уже открытого чата не требуется. Для продолжения в ChatGPT достаточно ссылки и короткого статуса. Если чат не видит GitHub, человек передаёт только краткую выжимку, а Codex перепроверяет источники перед действием.

## Доступность

| Сейчас, без VPS | После приёмки V3 на VPS | После реализации и приёмки №20 |
| --- | --- | --- |
| Читать задачи, PR, CI и опубликованные результаты. Собирать черновики задач и замечаний. Регистрировать согласованную карточку для команды в GitHub. Выполнять статическую сверку результата. | Оператор вручную импортирует подтверждённую команду и публикует результат. Координатор выполняет принятые задачи. Оператор смотрит живое состояние, выполняет отмену и разбирает сбои. | Автоматический импорт и публикация, устойчивый курсор, outbox и краткоживущие GitHub App tokens. Визуальная панель подключается отдельным этапом. |

Судья доступен через существующую отдельную команду в личной сессии Codex и не зависит от VPS. Этот проект описывает вызов, а текущая работа ограничена проектированием. Дополнительный LLM-агент и отдельный платный API не нужны.

Ближайшее решение Семёна и Толи — утвердить протокол, владельца запуска на Issue, порядок передачи и границы ручного пилота. Утверждение проекта само по себе не запускает задания и не меняет V3.
