# Офлайн-репетиция первого ручного пилота

28 ноября 2026 года. Основание — [решение Семёна в Issue №22](https://github.com/cryptospacerus-maker/forY-cassa-/issues/22#issuecomment-7238682883). Код V3 для прогона взят из `476444397c48183d04a3e856e742a33af93fa93f`.

Использовались временная SQLite и настоящие операции V3 `ingest`, очередь и `publish`. Ответы GitHub, допуск внешних прав, проверка и отправка Git-ветки результата подменены фикстурами. Действия Семёна и Толи, правила ручного оператора и передача результата проиграны в локальном сценарии. GitHub в ходе репетиции не менялся. Живого Worker и модели не было.

| № | Действие | Фактический результат |
|---|---|---|
| 1 | Семён инициирует синтетическую карточку 901, Толя — карточку 902. Толя импортирует обе | Два разных run. Автором каждого записан фактический инициатор |
| 2 | Семён повторяет свой запрос. Толя просит ту же версию карточки 901 | Повтор от Семёна возвращает тот же run. При запросе от Толи ручной оператор возвращает существующий run и не вызывает второй импорт. В очереди остаются два исходных запуска |
| 3 | Толя предлагает отменить run Семёна как управленческое решение. Семён предлагает отменить run Толи | Оба запроса отклонены на уровне ручного протокола, состояния run не изменились |
| 4 | Семён просит отменить свой run с выданной арендой шага | Отменён точный run, другой остаётся активным |
| 5 | После отмены шага имитируется heartbeat по старой аренде | V3 возвращает `lease_expired`, шаг в `needs_review`. Остановка процесса Worker требует сверки владельцем |
| 6 | Толя как оператор останавливает отдельный run Семёна при технической аварии | В ручном сценарии записаны точный run, причина и уведомление его владельца |
| 7 | Оператор публикует два терминальных исхода и повторяет публикацию результата Толи | Фикстура GitHub получает два комментария для двух run, каждый упоминает своего инициатора. Повтор возвращает тот же URL. Итог Толи содержит согласованный синтетический SHA |
| 8 | Толя передаёт следующий шаг Семёну по явно согласованному решению | В записи есть результат, URL, SHA, проверка, следующий шаг и получатель. Исторический владелец run Толи сохранён. При передаче новый run не создан |
| 9 | Контроль без ручной сверки: напрямую импортируется второй комментарий на карточку 901 с тем же ключом, но от другого автора | V3 создаёт другой run. Межавторский запрет двойного импорта обеспечивает ручной маршрут оператора. Техническая сериализация пока проектируется |

**Итог — 9 из 9 проверок репетиции.** Дополнительно выполнена штатная офлайн-регрессия V3, 27 из 27 тестов. В ней отдельно проверены точный SHA QA, отмена с выдачей lease, дедупликация, недоступность GitHub и восстановление публикации без второго комментария.

## Для независимого ревью

1. Сверить изменения `PROJECT.md`, протокола и примеров с решением в #22. Проверить разделение технической роли Толи и полномочий владельца конкретного run.
2. Повторить таблицу на синтетических комментариях и временной SQLite. Сохранить автора из комментария при импорте Толи. Для дубликата проверить число записей до и после. Для отрицательного контроля повторить импорт напрямую и увидеть различный идентификатор. Использовать фикстуры GitHub, не публиковать результаты в реальную карточку.
3. Сравнить SHA и URL в двух записях о результате, сверить @упоминания и получателя передачи. При отсутствии снимка хоста `status` считать неизвестным. При нестабильной сети проверять опубликованный маркер перед повторной публикацией.
4. Запустить штатную офлайн-регрессию:

   ```bash
   python -m unittest coordinator_v3.test_spike coordinator_v3.test_v3 coordinator_v3.test_hardening -q
   ```

Операторские полномочия и уведомления по аварии проверены как ручная процедура на фикстурах. Эксплуатационная приёмка worker и доставка реального уведомления остаются за #19. Толе предстоит независимо подтвердить протокол и назначение оператора.
