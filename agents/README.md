# Этап 2. Анализ ролей

На однодневной сборке основная потеря времени возникает на стыках: кто определяет смысл показателя, кто реализует расчёт и кто проверяет его глазами пользователя. Поэтому у каждого результата есть один владелец. Роль выбирается по задаче и доступна Семёну и Толе из любого рабочего аккаунта. Тоня получает проверенный сценарий для пилота и записи видео.

| Профиль | Когда подключать | Что передать дальше |
| --- | --- | --- |
| [Координатор](coordinator.md) | Запрос охватывает несколько результатов или исполнителей | Критерий приёмки, зависимости и общая версия |
| [Бизнес-аналитик](analyst.md) | Нужно выяснить, какое решение примет сотрудник по ответу агента | Сценарий, правила расчёта и контрольный пример |
| [Разработчик агента и интеграций](developer.md) | Нужен работающий инструмент, обработка данных или интеграция | Код, воспроизводимый запуск и самопроверка |
| [Разработчик интерфейса](interface.md) | Нужен пользовательский экран или интерактивный путь | Экран на согласованных данных и действия для демонстрации |
| [Тестировщик](tester.md) | Результат готов к независимой проверке | Вердикт по конкретной версии и воспроизводимые отклонения |

## Как выбирать состав

Для репетиции «Собери сводку обращений по темам» достаточно разработчика и тестировщика: ожидаемый результат уже опубликован в [примере](../examples/summary.md). Если магазин просит «показать проблемные платежи», первым подключается аналитик: нужно согласовать, что считать проблемой. После согласования примера данных разработчики логики и экрана могут работать параллельно. Координатор возвращает задачу конкретному исполнителю, если проверка общей версии выявляет расхождение.

## Как применить профиль сейчас

Перед запросом выполни [общие правила](../AGENTS.md), прочитай [решения проекта](../PROJECT.md) и указанную карточку. Команда для чата: «Работай по профилю agents/developer.md над задачей №…». Пока роли запускают Семён и Толя. Автоматический выбор и запуск исполнителей относится к следующему этапу.

При передаче оставь ссылку на версию, фактическую проверку и следующий шаг. Если изменился формат данных, перечисли зависимые карточки и версию нового решения. Повторно проверь результат перед сдачей.
